# STATUS

Состояние на 2026-08-19.

**Что это.** CLI-утилита к аппаратному кошельку Рутокен через PKCS#11-библиотеку
`wtpkcs11ecp`. Один процесс — одна команда.

**Что работает.** Все команды на месте и покрыты тестами: информация о библиотеке, слотах,
кошельках и токене, список ключей, генерация пары (`rsa1024`, `rsa2048`, `secp256`,
`ed25519`, `gost`), импорт master node по мнемонической фразе BIP39, удаление ключа по
номеру или всех объектов через `--force`, смена PIN, подпись готового хэша или данных.

**PIN-код.** Команды, которым нужна аутентификация, спрашивают PIN: `getpass` с терминала,
одна строка со stdin при перенаправлении. `--pin ЗНАЧЕНИЕ` по-прежнему принимается — это
осознанная возможность, а не режим по умолчанию. `--list-keys` без `--pin` показывает только
открытые ключи и stdin не читает.

**Тесты.** 76 тестов, все проходят: `python -m pytest` (проверено 2026-08-19 локально на
Python 3.11.15 и в CI на 3.14.7). Тесты подменяют PKCS#11-библиотеку мок-объектом — они
проверяют раскладку ctypes-структур, разбор аргументов и порядок вызовов, но **ничего не
говорят о поведении на реальном устройстве**.

**Проверка на железе.** Кошелька у агента нет, и на устройстве не проверялось ничего.
Библиотеку вендора загружали (`--library-info` отвечает `Rutoken Wallet PKCS #11 library`,
`Aktiv Co.`, версия 2.18), но дальше `C_OpenSession` возвращает «нет подключенного
кошелька». Всё, что касается ключей и PIN, проверяет владелец руками.

**CI.** Четыре workflow, все на каждый push. Три собирают бинарники под Linux, macOS и
Windows: скачивают вендорный архив, **сверяют его SHA-256**, собирают и проверяют, что
бинарник видит библиотеку (строка `Library Description`). Четвёртый, `tests.yml`, гоняет
`pytest`. Релизные артефакты собирает `release.yml` при публикации GitHub Release; тесты в
него не включены.

**Версия.** `version.py` — единственный источник, сейчас `0.7`, доступна через `--version`.
Релизы помечены тегами `v0.1`…`v0.6`; последний, `v0.6`, указывает на `3c17a07`, то есть
`main` уже ушёл вперёд. Changelog не ведётся.

**Вендорные библиотеки.** Берутся из GitHub Release этого же репозитория с тегом `3rdparty`,
не с сайта вендора. Контрольные суммы четырёх архивов закреплены в
`scripts/wtpkcs11ecp.sha256`; загрузчик сверяет их при каждом запуске, включая попадание в
кэш, и без пина отказывается работать.

**Известные пробелы.** Линтера и форматтера в проекте нет. Порядок обновления вендорной
библиотеки не записан — см. `docs/PLAN.md`.

**Где остановились.** Четыре правки по указанию владельца закрыты и проверены в CI.
Открытых задач в работе нет, см. `HANDOFF.md`.
