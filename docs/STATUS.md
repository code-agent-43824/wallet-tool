# STATUS

Состояние на 2026-08-19.

**Что это.** CLI-утилита к аппаратному кошельку Рутокен через PKCS#11-библиотеку
`wtpkcs11ecp`. Один процесс — одна команда.

**Что работает.** Все команды на месте и покрыты тестами: информация о библиотеке, слотах,
кошельках и токене, список ключей, генерация пары (`rsa1024`, `rsa2048`, `secp256`,
`ed25519`, `gost`), импорт master node по мнемонической фразе BIP39, удаление ключа по
номеру или всех объектов через `--force`, смена PIN, подпись готового хэша или данных.

**Тесты.** 47 тестов, все проходят: `python -m pytest` (проверено 2026-08-19,
Python 3.11.15, pytest 9.1.1). Тесты подменяют PKCS#11-библиотеку мок-объектом — они
проверяют раскладку ctypes-структур и порядок вызовов, но **ничего не говорят о поведении
на реальном устройстве**.

**Проверка на железе.** В этой сессии её не было и быть не могло: кошелька у агента нет.
Всё, что касается ключей и PIN, проверяет владелец руками.

**CI.** Четыре workflow, все на каждый push. Три собирают бинарники под Linux, macOS и
Windows и проверяют, что бинарник видит библиотеку (строка `Library Description`).
Четвёртый, `tests.yml`, гоняет `pytest` — заведён 2026-08-19, до этого тесты в CI не
запускались вовсе. Релизные артефакты собирает `release.yml` при публикации GitHub Release;
тесты в него не включены.

**Версия.** Отсутствует: ни `__version__`, ни тегов, ни changelog. Релизы собираются, когда
владелец публикует GitHub Release.

**Известные пробелы.** Загрузка вендорной библиотеки не проверяет SHA-256 (§7). PIN
передаётся аргументом командной строки и попадает в историю оболочки. Линтера и
форматтера в проекте нет. Подробности и вопросы владельцу — в `docs/PLAN.md`.

**Где остановились.** Правила разработки, карта кода и рабочие документы внедрены; тесты
подключены к CI. Незакрытыми остались три вопроса к владельцу из `docs/PLAN.md`:
SHA-256 для вендорной библиотеки, передача PIN аргументом, отсутствие версии.
