## 2026-08-21 — версия библиотеки должна быть частью URL

**Гипотеза.** Статическая папка с неизменяемой версией и SHA-256 в репозитории даст CI тот
же fail-closed контроль, что прежний GitHub Release, без хранения бинарников в репозитории.

**Что сделали.** Комплект `2.18.2.0` опубликовали под собственным URL; загрузчик принимает
точный относительный путь, а не ищет asset по подстрокам. Кэш включает версию и путь, но
даже при попадании в кэш SHA-256 проверяется заново.

**Проверка.** Серверный `SHA256SUMS` прошёл целиком. Основные библиотеки всех платформ и
исходный архив скачаны по HTTPS и совпали с серверными пинами. Холодная и тёплая ветки
загрузчика вернули один и тот же Linux x64 файл. При первой проверке Windows DLL ответила
403: исходный ZIP нёс режим `0770`, и Caddy не мог прочитать файл от другого пользователя.
После явного публичного режима `0644` обе Windows DLL скачиваются и проходят SHA-256.

**Вывод.** Публиковать новую версию надо в новую папку, не заменяя старые файлы; после
выкладки проверять именно публичные HTTPS URL, а не только файлы на сервере. Права доступа
являются частью этой проверки, хотя на контрольную сумму содержимого не влияют.
