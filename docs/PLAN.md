## Закрытый этап: правки по результатам разбора архитектуры

Владелец распорядился: чинить кривую, длину PIN при логине и коды возврата; разобраться с
дублированием и мёртвым кодом, не превращая код в абстракции — на нём учатся и по его
образцу пишут свой; остальное отложить.

- [x] Кривая: `secp256k1` вместо `secp256r1`. Сейчас в `CKA_EC_PARAMS` уходит OID
      `1.2.840.10045.3.1.7` (`SECP256R1_OID_DER`, `commands.py:99`) — и при генерации, и при
      импорте. Референс вендора (`KeyFromSeed.c`, `GenerateKeyAndGetSeed.c` из релиза
      `3rdparty`) по умолчанию использует `secp256k1Oid`, а `secp256r1` предлагает как
      закомментированную замену — байт в байт ту, что стоит в проекте. При этом мастер-ключ
      выводится через `HMAC-SHA512(key="Bitcoin seed")`, то есть BIP32 для биткойна, который
      определён над secp256k1. Владелец подтвердил: недосмотр. Нужный OID — `1.3.132.0.10`,
      DER `06 05 2B 81 04 00 0A`.
- [x] `C_Login` с длиной PIN в символах вместо байтов — `commands.py:1754`, только в удалении
      ключей; пять остальных вызовов считают байты. Для UTF-8 PIN логин не пройдёт, а попытка
      спишется со счётчика `ulUserRetryCountLeft`.
- [x] Коды возврата. Ни `main.py`, ни `commands.py` не вызывают `sys.exit`; любая команда
      завершается нулём даже после ошибки. Скрипт вокруг утилиты не может отличить успех от
      провала, и CI уже обходит это грепом по выводу.
- [x] Дублирование. Каркас сессии (`C_Initialize` → `C_OpenSession` → `C_Login` → флаги →
      `finally`) скопирован шесть раз почти дословно; `search_objects` определён трижды,
      `get_id` дважды, сортировка пар ключей трижды. Из последнего растёт расхождение
      нумерации `key-number` между командами. Свести к одному месту, оставив код плоским и
      читаемым: без лишней вложенности, «умных» абстракций и преждевременных оптимизаций.
- [x] Мёртвый код. `pkcs11.initialize_library` и `pkcs11.finalize_library` не вызываются
      нигде, кроме `monkeypatch` в тестах (24 раза); заглушки-лямбды в `pkcs11_command`
      существуют только ради моков; ветка `"hex"` у `format_attribute_value` недостижима из
      продакшена. Убрать вместе с тестовыми подпорками.

## Открыто, решения владельца нет

- [ ] Подтверждение для `--force`. Сейчас команда стирает все объекты токена без вопроса.
      Владелец: сделано намеренно, ради быстрой работы с утилитой; вопрос о подтверждении
      отложен, не поднимать без его слова.
- [ ] Подпись ключами `ed25519`. Генерация есть, `SIGN_KEY_CONFIG` ключ `CKK_EC_EDWARDS` не
      содержит, и `--sign` отвечает «не поддерживается». Путь построен как «посчитать хэш →
      подписать хэш», а Ed25519 подписывает сообщение целиком, поэтому это не одна строка в
      таблице, а отдельная ветка в `run_command_sign`.
- [ ] BIP39-passphrase. Сейчас зафиксирована пустой: при генерации `ulPassphraseLen = 0`,
      при импорте соль `b'mnemonic'` без добавки. Владелец: сделано для упрощения. Добавить
      параметр и работу с ним — фраза должна попадать и в механизм при генерации, и в соль
      PBKDF2 при импорте, иначе импорт перестанет совпадать с генерацией.
## Закрыто и не поднимать

- Мнемоническая фраза печатается в stdout при `--get-mnemonic`. Владелец: оставляем всегда,
  иначе фразу негде прочитать.
- Замечания по безопасности из разбора архитектуры (`CKA_SENSITIVE`/`CKA_EXTRACTABLE` не
  задаются, `--list-keys` готов напечатать `CKA_VALUE` закрытого ключа). Владелец: утилита
  предназначена для тестовых кошельков, а не для настоящих. Предупреждения в интерфейс и
  документацию не добавлять.
- Порядок обновления вендорных библиотек записан при переходе на статический сервер:
  новая версия публикуется в новой неизменяемой папке, проверяется по HTTPS, затем версия и
  SHA-256 меняются в репозитории. Старые versioned URL не перезаписываются.
